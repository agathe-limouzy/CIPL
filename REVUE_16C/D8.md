# Domaine D8 — Écrans généraux et sauvegarde

Revue 16c, lecture seule (31/10/2026). Fichiers lus en entier : `Save/*`, `Cloud/ExportCloud.cs`, `Cloud/SectionExport.cs`, `General/*`, `Tools/*`, `Menu/*`, plus les appelants (`BatimentManager`, `BatimentPrefab`, `LocatairePrefab`, `DemarrageCloud`, `EcritureCloud`, `ReglagePanel`) et les tests `TransfertEntrepriseTests`, `DonneesDisqueTests`, `CloudExportTests`.
Constat de fond : l'application démarre **uniquement** sur le cloud (`DemarrageLocal()` n'a plus d'appelant) ; une bonne partie du domaine « sauvegarde » (BackupService, MigrationDossiers, EntreprisePanel, changement d'emplacement) n'est plus atteignable, mais deux restes du mode local sont encore actifs sur le cloud et y font du dégât : le bouton « Transférer » (D8-01) et le repli de `GetSaveRoot` (D8-02).
Bilan : 1 Critique, 4 Majeurs, 5 Mineurs.

### D8-01 · Critique · « Transférer » reste actif sur le cloud : la fiche quitte le cloud pour un dossier local que personne ne lit
- Où : `Assets/Script/Save/TransfertEntrepriseUI.cs:119-125` (`Choisir` : destinations = registre local), `:79-92` (`ExecuterBatiment`), `:94-115` (`ExecuterLocataire`) ; bouton posé sans condition `Assets/Script/Batiment/BatimentPrefab.cs:519`, `Assets/Script/Locataire/LocatairePrefab.cs:310` ; registre alimenté sur le cloud par `Assets/Script/Save/EntrepriseBootstrap.cs:13` → `Assets/Script/Save/EntrepriseService.cs:63-70` et `Assets/Script/Facturation/ReglagePanel.cs:1356`.
- Problème : les destinations proposées sont les entrées du registre PlayerPrefs du mode local : « Mon entreprise » (la racine par défaut `…\LocalLow\CIPL\CIPL\CIPL_Saves`, enregistrée à chaque lancement **avant** l'ouverture du cloud) et les dossiers de documents des autres entreprises cloud ouvertes sur ce PC. Rien ne regarde `SessionCloud.Active`. Le transfert écrit `batiments/batiment_<id>.json` et copie les documents dans ce dossier, puis `DeleteBatiment` appelle `EcritureCloud.SupprimerBatiment` (suppression **sur le serveur**) et met le dossier d'origine en corbeille. Une entreprise cloud ne lit jamais `batiments/*.json` : la fiche n'apparaît nulle part.
- Scénario : installation neuve, entreprise cloud « SCI Rivoli » (dossier `Documents\CIPL\SCI Rivoli`). Le registre contient « Mon entreprise » (racine par défaut ; `DemarrageCloud.cs:252-253` dit bien que cette racine « est celle d'une autre entreprise »). Fiche bâtiment → « Transférer » → « Mon entreprise » → « Transférer ». Résultat : le bâtiment et ses locataires disparaissent du cloud pour **tous** les utilisateurs ; ses documents partent en corbeille locale puis sont marqués supprimés par la synchronisation ; le JSON dort dans `LocalLow\…\CIPL_Saves\batiments`, invisible. Même chose pour un locataire seul.
- Correction proposée : en tête de `Choisir` (ou dans `AjouterBouton`) : `if (SessionCloud.Active) { ConfirmDialog.Erreur("Le transfert vers une autre entreprise n'est pas encore disponible sur le cloud."); return; }` — ou ne pas créer le bouton. Et ne plus enregistrer de dossiers cloud dans le registre : `EnsureActiveRegistered` et `Register` (ReglagePanel:1356) sans effet quand `SessionCloud.Active`. Le vrai transfert est une opération serveur (CONCEPTION §7, « TransfertEntreprise → Demain »).
- Test : EditMode — nouvelle règle pure `RegleTransfert.Destinations(IEnumerable<Entreprise> registre, string racineActive, bool cloud)` → vide si `cloud`, et `EntrepriseService` n'enregistre rien si `cloud` ; Play — entreprise cloud, fiche bâtiment et fiche locataire : pas de bouton « Transférer » (le parcours M1 de `PARCOURS_TEST_CIPL.md:357` le cite encore : à mettre à jour).
- Confiance : haute (flux suivi de bout en bout ; aucune garde cloud dans `TransfertEntrepriseUI` ; PARCOURS_TEST M1 confirme que le bouton est visible dans l'interface cloud).

### D8-02 · Majeur · `GetSaveRoot` se replie sur la racine de « Mon entreprise » quand le dossier de l'entreprise cloud manque
- Où : `Assets/Script/Save/SaveLocationService.cs:16-38` ; consommateurs de la racine « vivante » : `Assets/Script/Save/DossiersDonnees.cs:74`, `Assets/Script/Cloud/ExportCloud.cs:61,78,140-154` ; règle écrite par l'auteur : `Assets/Script/Cloud/DemarrageCloud.cs:252-253` (« Jamais la racine par défaut : c'est celle d'une autre entreprise »).
- Problème : le repli vers `GetDefaultRoot()` a été écrit pour le mode local (disque débranché). Sur le cloud, la racine est le dossier de l'entreprise (Drive ou `Documents\CIPL\<nom>`) ; s'il disparaît en cours de session (Drive déconnecté, clé USB, dossier renommé), `GetSaveRoot()` renvoie, après un seul toast, `…\CIPL_Saves` = les données pré-cloud de « Mon entreprise ». Tout ce qui lit la racine au moment de l'appel travaille alors dans le dossier d'une autre entreprise : les nouveaux PDF (`DossiersDonnees.Racine`) y sont rangés, et `ExportCloud.Locaux` y liste `Batiment/…` → les documents de « Mon entreprise » sont exportés comme ceux de l'entreprise cloud, mélangés aux siens. `DocumentsCloud`, lui, a été démarré avec la racine du Drive (`DirectCloud.cs:54`) : le PDF écrit dans le dossier de repli n'est jamais envoyé au cloud.
- Scénario : « SCI Rivoli » en mode Drive, Google Drive se ferme ; l'admin clique « Exporter… » → l'export contient les dossiers `Batiment/<anciens bâtiments locaux>/…` de « Mon entreprise » ; une facture émise pendant ce temps est écrite dans `LocalLow\…\CIPL_Saves\Batiment\SCI…\…` ; au retour du Drive, `GetSaveRoot` rebascule, le PDF est « introuvable » et n'est pas sur le cloud.
- Correction proposée : pas de repli sur le cloud : dans `GetSaveRoot`, `if (SessionCloud.Active && !string.IsNullOrEmpty(custom)) return custom;` (le dossier enregistré, même absent : les écritures échouent bruyamment via `AtomicFile`, et `DossierDocuments` retraite le cas à l'ouverture suivante) ; au besoin, repli vers `DemarrageCloud.DossierLocal(e)` (par entreprise), jamais vers `GetDefaultRoot()`. `ExportCloud.Exporter` refuse si `!Directory.Exists(racine)` (« dossier des documents introuvable »).
- Test : EditMode — extraire une règle pure `SaveLocationService.Racine(string enregistree, bool existe, bool cloud, string defaut)` : `cloud && !existe` → `enregistree` ; `!cloud && !existe` → `defaut`. Play — renommer le dossier de l'entreprise pendant la session, émettre une facture : message d'erreur, rien écrit dans `LocalLow`.
- Confiance : moyenne — le code du repli est certain, le scénario demande que le dossier disparaisse en cours de session.

### D8-03 · Majeur · Fermer l'application pendant un enregistrement cloud en vol le perd sans prévenir
- Où : `Assets/Script/General/FermetureGuard.cs:89-111` (`AutoriserFermeture` ne regarde que `NomsEnEdition`) ; `Assets/Script/Cloud/EcritureCloud.cs:249-263` (`Enregistrer` = tâche asynchrone `_file`, `await SessionCloud.Jeton()` puis HTTP), `:517` (`EnregistrementEnCours`, lu seulement par `FactureEnvoiAuto.cs:425`), `:644-648` (`OnApplicationQuit` : `GarderCopie` + `LibererTout`, sans attendre `_file`).
- Problème : une modification validée (fiche enregistrée, écran fermé) n'est plus « en édition » ; la fermeture passe ; le processus s'arrête et la continuation asynchrone ne s'exécute jamais. `_cache` n'étant avancé qu'après l'accord du serveur, la copie locale écrite à la fermeture porte l'ancien état. Au relancement, la fiche est relue sur le serveur **sans** la modification, sans aucun message.
- Scénario : modifier le loyer, « Enregistrer », fermer la fenêtre dans la seconde (ou jeton expiré → rafraîchissement en cours) → au relancement, l'ancien loyer.
- Correction proposée : dans `AutoriserFermeture` : `if (EcritureCloud.EnregistrementEnCours) { UndoToast.Instance?.ShowInfo("Enregistrement en cours, fermeture dans un instant…"); EcritureCloud.QuandTermine(() => { _quitterConfirme = true; Application.Quit(); }); return false; }` avec `QuandTermine` = `_file.ContinueWith(…, TaskScheduler.FromCurrentSynchronizationContext())`. Même attente dans `QuitButton` (via la méthode partagée de D8-04).
- Test : EditMode — règle pure `FermetureGuard.Decision(int fichesEnEdition, bool enregistrementEnCours)` → `Attendre` / `Prevenir` / `Fermer`. Play — « Enregistrer » puis Alt+F4 immédiat ; relancer ; la valeur doit être là.
- Confiance : moyenne (fenêtre de 0,2 à 2 s selon le réseau, mais rien ne la couvre).

### D8-05 · Majeur · Les écrans de saisie (facture, achat, charge, révision, départ…) ne sont pas couverts par la garde de fermeture
- Où : `Assets/Script/General/FermetureGuard.cs:29-42` (`NomsEnEdition` ne lit que `PrefabBatLoc.EnEdition`) ; `Assets/Script/PrefabBatLoc.cs:19` ; écrans qui tiennent une fiche : `Assets/Script/Cloud/EcritureCloud.cs:340-346` (`_tenus`, avec `Nom` et `Actif`, non exposé).
- Problème : les écrans modaux (FactureLoyerPanel, AchatFormPanel, ChargePanel, RevisionPanel, DepartPanel…) gardent leurs champs jusqu'à leur propre bouton d'enregistrement ; ils ne rendent pas la fiche « en édition », donc la fermeture ne prévient de rien. - Scénario : ouvrir « Achats », saisir un prêt, fermer la fenêtre → aucune alerte, saisie perdue.
- Correction proposée : `EcritureCloud.FichesTenues()` → `_tenus.Where(t => t.Actif()).Select(t => t.Nom).Distinct()` ; `FermetureGuard.NomsEnEdition` = union des deux listes.
- Test : EditMode — `FermetureGuard.NomsEnEdition(IEnumerable<string> fiches, IEnumerable<string> tenues)` pure (doublons retirés) ; Play — écran Achats ouvert avec une saisie, croix → dialogue.
- Confiance : moyenne — le code est certain ; la limitation aux « fiches » n'est pas écrite comme décision (REVUE :1756 parle de fiches, CONCEPTION §7 dit « prévenir si une saisie est en cours »).

## Points vérifiés sans défaut
- **AtomicFile** : `.tmp` → `File.Replace` avec `.bak` (ou `Move` à la première écriture), `.tmp` effacé sur échec, `ReadAllText` distingue absent / lisible / illisible. Utilisé par `BatimentManager.SaveBatiment`, `ReglageService` (3 écritures), `CopieLocale`, `ImportLocal`, `DocumentsCloud` (état et réceptions en `tmp` + `Replace`), `TransfertEntreprise`. Les `File.WriteAllText` restants sont des fichiers jetables (marqueur de migration, export, HTML temporaire du PDF, version visée).
- **MigrateData** : refuse une destination déjà peuplée (M5 corrigé, testé dans `DonneesDisqueTests`), comparaison de chemins insensible à la casse, retour à l'ancienne racine sur échec sans retirer l'entreprise de la liste.
- **TransfertEntreprise** : destination écrite avant tout retrait de l'origine ; la version remplacée part d'abord en corbeille ; `reglage.json` ou bâtiment illisible → échec sans écriture ; listes de charges retrouvées par nom ; chemins absolus rendus relatifs ; `Apercu` n'écrit rien (13 tests `TransfertEntrepriseTests`).
- **Corbeilles** : suppression d'un bâtiment → dossier déplacé en `corbeille_batiments`, jamais purgé ; restauration refusée si l'entreprise active a changé (`BatimentPrefab.cs:498-514`) ; photos → `corbeille_photos`, purge 7 jours (testée).
- **ExportCloud / SectionExport** : entreprise ouverte seulement (racine par entreprise `cipl_dossier_<id>`, table `documents` filtrée sur `entreprise_id`), secrets dans un fichier à part donc absents de `reglage.json`, corbeilles et aperçus exclus (`SyncDocuments.Racines/Partage`, `DossiersDonnees.Nouveau`), nom de dossier libre (jamais d'écrasement), indisponible hors ligne, bouton verrouillé pendant l'export, `_corps` détruit géré. Testé (`CloudExportTests`). Réserve : D8-02 quand le dossier de l'entreprise manque.
- **SauvegardeDeFermeture** : inactive sur le cloud, refuse une racine changée depuis le chargement, compte les échecs.
- **FermetureGuard.ConfirmerPerteSaisies** : posé avant les sept opérations qui rechargent (changement d'emplacement ×2, défaut ×2, Activer/Ouvrir/Créer) et avant le transfert ; action directe quand rien n'est en édition.
- **ConfirmDialog** : la fenêtre est masquée avant d'exécuter l'action (pas de double clic possible) ; les écouteurs sont remplacés à chaque `Show` (pas de cumul) ; `Erreur` masque « Annuler » et `Show` le rétablit ; `parseCtrlCharacters` désactivé (chemins Windows). Un `Show` pendant un autre remplace le dialogue sans exécuter l'action en attente — sans dommage trouvé.
- **UndoToast** : un seul toast, minuterie relancée, `Annuler` masqué pour une info ; aucun `ShowInfo` ne suit immédiatement une suppression (le bouton « Annuler » reste disponible 8 s).
- **SaisieNumerique / SaisieDate** : culture invariante, point et virgule interchangeables, espaces (dont insécables), €, % ; dates en formats explicites `d/M/yyyy` (testés).
- **HomeAlert** : locataires archivés exclus (archive ⇒ départ saisi ⇒ `RenouvellementProche`, `ResiliationProche`, `RevisionIndiceSuivie` faux ; `FacturationAlertes.Pour` et les objectifs testent `archive`) ; tri stable par priorité ; filtres cohérents entre tuiles et compteurs.
- **UIZoom** : facteur borné [0,8 ; 1,75], résolution d'origine lue une fois ; **InputFieldScrollFix**, **PanelResizer**, **MenuManager/MenuItem** (onglet voisin après suppression, libellé tronqué, `Name` jamais nul grâce à `NomParDefaut`), **Plateforme**, **QuickCalcInline** : rien à signaler.
